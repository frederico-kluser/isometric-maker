Sprites 3D: sprite única nas faces do cubo

A mesma sprite isométrica aplicada como textura única nas 3 faces visíveis do cubo (+X, +Z, +Y) — sem recortes, sem dewarp, sem separação por face.

Three.js cube3d.ts 2026-08-04 onda2

Abordagem final

Blocos com arte gerada (PixelLab v2, faceUrls) têm sprites isométricos que mostram as 3 faces visíveis do cubo numa única imagem (projeção 2:1, 48×53 px).

A sprite é carregada como UMA textura e aplicada nas 3 faces visíveis do BoxGeometry:

Face 3DBoxGeometryTextura
Direita (SE)+X (índice 0)Sprite inteira
Topo+Y (índice 2)Sprite inteira
Esquerda (SW)+Z (índice 4)Sprite inteira
Ocultas−X, −Z, −YCor sólida HSL

A mesma sprite — sem recortes, sem dewarp, sem separação em 3 texturas. Cada face visível mostra a sprite isométrica completa.

O que foi removido

  • dewarpFaces — 105 linhas de projeção inversa pixel a pixel (onda 1: substituída por crop)
  • cropFaces — 65 linhas de recorte em 3 regiões (onda 2: substituída por sprite única)
  • extractFacesFromUrl — carregamento + crop + 3 canvas textures
  • materialsFromExtractedFaces — mapeamento de 3 texturas para 6 faces
  • loadImage — carregamento de Image para canvas

materialsWithSingleSprite

function materialsWithSingleSprite(
  tex: THREE.Texture,
  hue: number,
): CubeMaterials {
  const hiddenColor = new THREE.Color().setHSL(hue / 360, 0.45, 0.34);
  const bottomColor = new THREE.Color().setHSL(hue / 360, 0.45, 0.22);

  const spriteMat = new THREE.MeshLambertMaterial({ map: tex });
  const hidden = new THREE.MeshLambertMaterial({ color: hiddenColor });
  const bottomMat = new THREE.MeshLambertMaterial({ color: bottomColor });

  // [0]=+X, [1]=-X, [2]=+Y, [3]=-Y, [4]=+Z, [5]=-Z
  return {
    materials: [
      spriteMat, // +X  — sprite inteira
      hidden,    // −X  — oculta
      spriteMat, // +Y  — sprite inteira
      bottomMat, // −Y  — fundo
      spriteMat, // +Z  — sprite inteira
      hidden,    // −Z  — oculta
    ],
    hasTexture: true,
  };
}

Iterações

Onda 1 — dewarp → crop (commit 5c200da)

Substituiu o dewarp de 105 linhas (projeção inversa pixel a pixel) por crop de 3 regiões retangulares do sprite. Cada região virava uma textura separada para a face correspondente.

Problemas encontrados na revisão adversarial:

  • Laterais incluíam arte do topo (crop começava na linha 0)
  • Pixels transparentes viravam preto opaco
  • Exceção quebrava fallback procedural

Corrigidos no mesmo agente (commit 83ed744 na worktree).

Onda 2 — sprite única (commit c346332)

Removeu completamente o conceito de "recortar em 3 partes". A sprite isométrica é carregada como uma textura via loadTexture (que já existia no módulo) e aplicada diretamente nas 3 faces visíveis.

Diferença fundamental: em vez de 3 texturas separadas (uma por face), a mesma textura cobre +X, +Z e +Y. Cada face mostra a sprite isométrica completa — a mesma imagem nos 3 lados visíveis do cubo.

Nota: O caminho faceUrls (v2) só é usado por blocos com manifest.version === 2. Assets atuais são v3 (baseUrl/spritesheetUrl) e usam materialsWithSingleTexture — que já aplica uma textura a todas as faces laterais. A mudança unifica o comportamento: tanto v2 quanto v3 agora usam textura única.
