Sprites 3D: dewarp → crop simples

Substituição do pipeline de de-warp (projeção inversa pixel a pixel) por crop simples (recorte 1:1 via drawImage) nas texturas dos cubos 3D do editor de mapa.

Three.js cube3d.ts 2026-08-04

O que mudou

O editor 3D usa cubos Three.js (BoxGeometry) para representar blocos no mapa. Blocos com arte gerada (PixelLab v2) têm sprites isométricos que mostram as 3 faces visíveis do cubo numa única imagem (projeção 2:1, 48×53 px).

O código anterior usava de-warp: uma função de 105 linhas que aplicava a inversa da projeção isométrica pixel a pixel para separar o sprite em 3 texturas quadradas independentes (topo, esquerda, direita), uma para cada face do BoxGeometry.

O novo código usa crop simples: 25 linhas que recortam 3 retângulos do sprite com ctx.drawImage() — sem transformação de pixels, sem projeção inversa. As texturas são aplicadas diretamente às faces do cubo; o mapeamento UV do BoxGeometry estica cada uma para preencher a face.

Antes: dewarp (105 linhas)

A função dewarpFaces usava getImageData + iteração pixel a pixel com a inversa da projeção 2:1:

  • Topo: inversa exata do losango → quadrado W×W: sx = (c − r + W) / 2, sy = (c + r) · H / (2W)
  • Laterais: cada coluna do paralelogramo esticada para W linhas do quadrado, usando columnBounds e diamondRow do iso-core
  • Saída: 3 texturas quadradas W×W (48×48), 100% opacas

Depois: crop (25 linhas)

A função cropFaces usa ctx.drawImage() para recorte 1:1:

function cropFaces(
  sourceImage: HTMLImageElement,
  geom: IsoCubeGeometry,
  hue: number,
): { top: HTMLCanvasElement; left: HTMLCanvasElement; right: HTMLCanvasElement } {
  const { spriteHeight: h, tileWidth, tileHeight } = geom;
  const half = tileWidth / 2;

  function cropRect(x: number, y: number, cw: number, ch: number, fill: string) {
    const canvas = document.createElement('canvas');
    canvas.width = cw;
    canvas.height = ch;
    const ctx = canvas.getContext('2d');
    if (!ctx) throw new Error('canvas 2d indisponível para recorte de face');
    ctx.imageSmoothingEnabled = false;
    ctx.fillStyle = fill;
    ctx.fillRect(0, 0, cw, ch);            // preenche fundo antes do sprite
    ctx.drawImage(sourceImage, x, y, cw, ch, 0, 0, cw, ch);
    return canvas;
  }

  const topFill = `hsl(${hue}, 45%, 62%)`;
  const sideFill = `hsl(${hue}, 45%, 47%)`;
  const top = cropRect(0, 0, tileWidth, tileHeight, topFill);
  const right = cropRect(half, tileHeight, half, h - tileHeight, sideFill);
  const left = cropRect(0, tileHeight, half, h - tileHeight, sideFill);
  return { top, left, right };
}

Bugs encontrados na revisão adversarial

A revisão adversarial renderizou os cubos em WebGL headless e comparou pixel a pixel. Três problemas foram encontrados e corrigidos:

Bug 1 — Laterais incluíam arte do topo

O crop original das laterais cropRect(0, 0, half, h) começava na linha 0 e pegava todas as 53 linhas. As linhas 0–23 contêm a metade do losango do topo — essa arte aparecia na parede lateral.

Correção: Laterais agora começam em tileHeight (linha 24), com altura spriteHeight - tileHeight (29 linhas).

Bug 2 — Pixels transparentes viravam preto opaco

As texturas de crop têm pixels transparentes (margens do losango, cantos fora da silhueta, linhas vazias no fim do sprite). MeshLambertMaterial com transparent: false (default) renderiza alpha=0 como preto (0,0,0). O dewarp anterior preenchia todos os pixels — saída 100% opaca.

Correção: ctx.fillRect() com a cor HSL da face antes do drawImage(). Topo: 62% lightness; laterais: 47% — mesmas cores do cubo procedural.

Bug 3 — Exceção quebrava fallback procedural

cropFaces lança throw new Error se getContext('2d') retornar null. O código antigo retornava null e o chamador fazia fallback para material procedural. A exceção subia até createCubeMaterials e quebrava a criação do bloco inteiro.

Correção: try/catch em extractFacesFromUrl — exceção retorna null e cai no fallback procedural.

Nota: O caminho faceUrls (v2) só é usado por blocos com manifest.version === 2. Todos os assets atuais são v3 — o bug não era visível no app, mas o código estava quebrado e precisava ser consertado.
