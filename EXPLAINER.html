Sprites 3D: sprite única nas faces do cubo

Sprite isométrica única esticada sobre as 3 faces visíveis do cubo via UV mapping customizado no BoxGeometry — cada face sampleia a região correta da sprite, sem recortes e sem duplicação.

Three.js cube3d.ts 2026-08-04 onda3 · UV mapping

Abordagem final: UV mapping customizado

Blocos com arte gerada (PixelLab v2, faceUrls) têm sprites isométricos (48×53 px) que mostram as 3 faces visíveis do cubo. A sprite é carregada como UMA textura e aplicada nas faces +X, +Z, +Y — mas com UVs customizados para que cada face sampleie apenas a sua região:

Face 3DBoxGeometryRegião UV (u, v)Parte do sprite
Direita (SE)+X (grupo 0)u=[0.5, 1], v=[29/53, 1]Metade direita, abaixo do topo
Topo+Y (grupo 2)u=[0, 1], v=[29/53, 1]Topo (bounding box do losango)
Esquerda (SW)+Z (grupo 4)u=[0, 0.5], v=[29/53, 1]Metade esquerda, abaixo do topo
Ocultas−X, −Z, −YUV padrão (não usado)Cor sólida HSL

Como funciona: createSpriteGeometry() clona o BoxGeometry compartilhado e reescreve o atributo UV dos vértices de cada face visível. A função remapFaceUv() encontra os 4 vértices únicos de cada grupo de material e aplica a transformação de UV. A geometria customizada é cacheada e reutilizada por todos os cubos com sprite.

createSpriteGeometry — UV mapping

const SPRITE_UV = {
  uFold: (CANONICAL_CUBE.tileWidth / 2) / CANONICAL_CUBE.spriteWidth,  // 0.5
  vRoofBottom: 1 - CANONICAL_CUBE.tileHeight / CANONICAL_CUBE.spriteHeight, // 29/53
} as const;

function createSpriteGeometry(geom: IsoCubeGeometry): THREE.BoxGeometry {
  const cached = spriteGeometryCache.get(geom);
  if (cached) return cached;

  const geo = sharedBox.clone(); // nunca muta a geometria compartilhada

  // +X (right): metade direita, faixa das laterais
  remapFaceUv(geo, BOX_GROUP.right, (u, v) => [
    SPRITE_UV.uFold + u * (1 - SPRITE_UV.uFold),
    v * SPRITE_UV.vRoofBottom,
  ]);

  // +Z (front): metade esquerda, faixa das laterais
  remapFaceUv(geo, BOX_GROUP.front, (u, v) => [
    u * SPRITE_UV.uFold,
    v * SPRITE_UV.vRoofBottom,
  ]);

  // +Y (top): largura cheia, faixa do topo
  remapFaceUv(geo, BOX_GROUP.top, (u, v) => [
    u,
    SPRITE_UV.vRoofBottom + v * (1 - SPRITE_UV.vRoofBottom),
  ]);

  spriteGeometryCache.set(geom, geo);
  return geo;
}

Iterações

Onda 1 — dewarp → crop (commit 5c200da)

Substituiu o dewarp de 105 linhas (projeção inversa pixel a pixel) por crop de 3 regiões retangulares do sprite. Cada região virava uma textura separada para a face correspondente.

Problemas encontrados na revisão adversarial:

  • Laterais incluíam arte do topo (crop começava na linha 0)
  • Pixels transparentes viravam preto opaco
  • Exceção quebrava fallback procedural

Corrigidos no mesmo agente (commit 83ed744 na worktree).

Onda 2 — sprite única (commit c346332)

Removeu o conceito de "recortar em 3 partes". A sprite é carregada como uma textura e aplicada nas 3 faces visíveis.

Problema: Com UVs padrão do BoxGeometry, cada face mostrava a sprite isométrica COMPLETA — o cubo parecia ter 3 cópias da mesma sprite, cada uma com os 3 lados em miniatura.

Onda 3 — UV mapping (commit a1a1f59) ✓ SOLUÇÃO FINAL

Resolve o problema da onda 2. Implementa createSpriteGeometry() que clona o BoxGeometry e reescreve os UVs das faces +X, +Z, +Y:

  • +X: u=[0.5,1], v=[29/53,1] → metade direita da sprite
  • +Z: u=[0,0.5], v=[29/53,1] → metade esquerda da sprite
  • +Y: u=[0,1], v=[29/53,1] → topo da sprite

remapFaceUv() percorre os grupos de material do BoxGeometry indexado, encontra os 4 vértices únicos de cada face e aplica a transformação. Geometria cacheada; campo opcional geometry em CubeMaterials evita alterar scene3d.ts.

Nota: O caminho faceUrls (v2) só é usado por blocos com manifest.version === 2. Assets atuais são v3 (baseUrl/spritesheetUrl) e usam materialsWithSingleTexture.
