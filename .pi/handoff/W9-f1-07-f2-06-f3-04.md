### API pública

```ts
export interface AnimateInput {
  readonly characterId: string;
  readonly seed: number;
  readonly imageSize: { readonly width: number; readonly height: number };
  readonly mode: 'template' | 'v3';
  readonly templateAnimationId?: string;    // ex.: 'walking-4-frames'
  readonly actionDescription?: string;      // ex.: 'running forward'
  readonly frameCount?: number;
  readonly keepFirstFrame?: boolean;        // true só com mode='v3'
  readonly outputDir: string;
}

export interface AnimateResult {
  readonly frames: Record<string, string[]>;
}

export interface AnimateCeiling {
  readonly maxGenerations: number;
  readonly maxCostUsd: number;
  readonly label: string;  // "até N gerações · até US$ X"
}

export function animateCeiling(input: AnimateInput): AnimateCeiling
export function estimateAnimate(input: AnimateInput, monthSpent: number, sessionSpent: number): BudgetReport
export async function animateCharacter(client: PixelLabClient, input: AnimateInput, opts?: {
  readonly ledgerPath?: string;
  readonly onLog?: (msg: string) => void;
  readonly pollInitialMs?: number;   // default 5000; use 0 em testes
  readonly pollSteadyMs?: number;    // default 10000
  readonly pollTimeoutMs?: number;   // default 900000
}): Promise<AnimateResult>
```

### Decisões de design

1. **Mode template para walking, v3 para running/jumping.** `walking-4-frames` é usado como `template_animation_id` (confirmado por E2). Para correr e pular, `mode:'v3'` com `action_description` + `frame_count: 4`.
2. **keep_first_frame é mode:'v3' APENAS.** Quando `mode:'v3'`, `keep_first_frame: true` é sempre enviado.
3. **directions SEMPRE explícito com as 8.** O array canónico é passado em todas as chamadas, independentemente do modo.
4. **Ledger por job (direcção).** Uma linha no ledger para a submissão principal e uma linha por job após poll. Usage cru em cada linha.
5. **Teto na tela ANTES do botão.** `animateCeiling` devolve o pior caso formatado: "até N gerações · até US$ X.XX". Template: 8 gens; v3: 320 gens (40/dir × 8).
6. **Idempotência.** Hash determinístico sobre (characterId, seed, mode, templateId/action, frameCount). Se os PNGs já existirem, NENHUMA chamada é feita. Testado: segunda execução faz 0 requisições.
7. **Poll configurável.** `pollInitialMs`, `pollSteadyMs`, `pollTimeoutMs` nas opções. Útil para testes com cliente falso (usar 0).

### Limitações conhecidas

- O módulo NÃO está integrado no fluxo de geração (`api.ts`). A integração é uma task separada.
- A idempotência verifica se os PNGs existem no disco, não consulta o studio.json.

## F2-06 — Diagonal picking

### Arquivos

- `tools/map-builder/src/picking.ts` — `pick`, `pickWithHighlight`, `DEFAULT_GEOMETRY`
- `tools/map-builder/src/picking.test.ts` — 8 testes

### API pública

```ts
export interface ProjectGeometry {
  readonly tileWidth: number;
  readonly tileHeight: number;
  readonly zStep: number;
}

export const DEFAULT_GEOMETRY: ProjectGeometry  // 64×32, zStep=16

export interface PickResult {
  readonly cell: { readonly x: number; readonly y: number; readonly z: number };
  readonly blockType: string;
  readonly isFloor: boolean;
}

export interface HighlightResult extends PickResult {
  readonly floorCell: { readonly x: number; readonly y: number; readonly z: 0 };
}

export function pick(sx: number, sy: number, map: MapData, geom?: ProjectGeometry): PickResult | null
export function pickWithHighlight(sx: number, sy: number, map: MapData, geom?: ProjectGeometry): HighlightResult | null
```

### Decisões de design

1. **Aritmética pura, sem hit-test.** O algoritmo percorre os níveis de z do máximo ao mínimo. Para cada z, calcula `screenToCell(sx, sy, z)` e consulta a ocupação. A propriedade da diagonal garante que cada nível de z cai na célula correcta — sem ray casting.
2. **Caminhada diagonal.** `screenToWorld(sx, sy, z+1) ≡ screenToWorld(sx, sy, z) + (0.5, 0.5)` com a geometria padrão. Dois níveis de z = uma célula diagonal completa.
3. **Piso vs ausência.** Se nenhuma célula no raio tem bloco, devolve a célula de piso (z=0) com `isFloor: true`. Se a coluna de piso não existe no mapa, devolve `null` ("nenhuma").
4. **Realce com UMA célula.** `pickWithHighlight` devolve a célula seleccionada e a célula de piso (z=0 na mesma diagonal) para realce visual.

### Limitações conhecidas

- A geometria (`ProjectGeometry`, `screenToWorld`, `screenToCell`) está inline no módulo porque `iso-core/src/geometry.ts` importa `project.ts` que usa `node:crypto` (incompatível com browser via Vite).
- O módulo não está integrado no `app.ts` do map-builder. A integração (registar o evento de clique e chamar `pick`) é uma task separada.

## F3-04 — Pulo com parábola

### Arquivos

- `packages/iso-core/src/jump.ts` — `JumpState`, `createJump`, `effectiveZ`, `visualOffsetY`, `advanceJump`, `isJumpComplete`, `isJumpTransitioning`
- `packages/iso-core/src/jump.test.ts` — 19 testes

### API pública

```ts
export interface JumpState {
  readonly zOrigin: number;
  readonly zDest: number;
  readonly progress: number;  // 0..1
}

export const NO_JUMP: JumpState

export function createJump(zOrigin: number, zDest: number): JumpState
export function effectiveZ(state: JumpState): number       // SEMPRE inteiro
export function visualOffsetY(progress: number, jumpHeightPx: number): number  // parábola em px
export function advanceJump(state: JumpState, dt: number, jumpDuration: number): JumpState
export function isJumpComplete(state: JumpState): boolean
export function isJumpTransitioning(state: JumpState, prevProgress: number): boolean
```

### Decisões de design

1. **z é DISCRETO em todo o instante.** `effectiveZ` devolve `zOrigin` quando progresso < 0.5 e `zDest` quando progresso ≥ 0.5. O modelo nunca vê um z fraccionário. Invariante testado em 1001 passos.
2. **Parábola é DECORAÇÃO.** `visualOffsetY(progress, jumpHeightPx)` devolve o deslocamento vertical em píxeis de ecrã. Fórmula: `-4 * h * p * (1-p)`. Pico em p=0.5, simétrica. Separada do modelo — não altera o estado.
3. **Colisão no z efectivo.** A regra de colisão usa `effectiveZ`, que é sempre `zOrigin` ou `zDest`. O `visualOffsetY` NUNCA afecta a colisão. Testado: em todos os passos, `effectiveZ ∈ {zOrigin, zDest}` e `Number.isInteger(z)`.
4. **Transição de z no meio do pulo.** `isJumpTransitioning` detecta o cruzamento de 0.5 — útil para o sistema de colisão saber quando actualizar o z do modelo.

### Limitações conhecidas

- O módulo não trata dano de queda ou física de aterragem. Isso pertence ao sistema de vida.
- `advanceJump` não valida se `zDest` é entrável (a verificação de caminhabilidade é feita pelo sistema de colisão antes de iniciar o pulo).

## Destinatários nomeados

- **Integração F1-07 no flow de geração:** `animateCeiling` deve ser chamado antes de `POST /api/generate` para mostrar o custo. `animateCharacter` substitui `generatePose` para os modos template e v3. O endpoint `POST /api/generate` em `api.ts` precisa ser estendido para usar `animate.ts`.
- **Integração F2-06 no editor de mapa:** `pick` deve ser chamado no handler de clique do canvas em `app.ts`. A célula devolvida pode ser usada para highlight e para edição (place/remove block). `pickWithHighlight` devolve a célula de piso para realce.
- **F3-04 no motor de jogo:** `JumpState` deve ser integrado em `MovementState` (F3-01) ou usado em paralelo. `visualOffsetY` deve ser aplicado ao sprite durante a renderização. A regra de colisão (usar `effectiveZ`) deve ser seguida pelo sistema de pathfinding/collision.
