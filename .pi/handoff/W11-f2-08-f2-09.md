## F2-08 — Autoladrilhamento por máscara de 4 bits

### Arquivos

- `tools/map-builder/src/autotile.ts` — Motor de autoladrilhamento
- `tools/map-builder/src/autotile.test.ts` — 47 testes

### API pública

#### autotile.ts

```ts
export function buildMask(
  blocks: BlockStore,
  x: number, y: number, z: number,
  terrain: string,
): number

export function findTileForMask(
  rules: readonly TileRule[],
  mask: number,
  terrain: string,
): TileRule | undefined

export function autotile(
  blocks: BlockStore,
  x: number, y: number, z: number,
  terrain: string,
  rules: readonly TileRule[],
): number

export function missingMasks(
  rules: readonly TileRule[],
  terrain: string,
): number[]

export function affectedCells(
  x: number, y: number,
): ReadonlyArray<{ x: number; y: number }>
```

- `buildMask`: Constrói máscara de 4 bits a partir dos vizinhos. bit0=N, bit1=L, bit2=S, bit3=O (convenção F2-04/AB-371).
- `findTileForMask`: Procura regra por máscara + terreno.
- `autotile`: Calcula máscara e devolve `tileIndex`. Lança `Error` em pt-BR se não houver peça.
- `missingMasks`: Devolve lista ordenada de máscaras (0–15) sem cobertura para um terreno.
- `affectedCells`: Devolve as 5 células (central + 4 vizinhos) que precisam de ser re-ladrilhadas quando um bloco muda.

### Decisões de design

1. **Máscara por vizinhança, não por canto.** O cartão pede máscara de 4 bits a partir dos vizinhos cardeais (N, L, S, O). Isto é Wang por aresta (`edge/4`), não por canto (`corner/4`). A máscara é calculada verificando se cada vizinho tem o MESMO terreno no MESMO nível z.

2. **Consumo de tile_rules da API, não tabela à mão.** `findTileForMask` recebe `TileRule[]` (parse de F2-04) e procura por `mask` + `terrain`. Nenhuma tabela hardcoded.

3. **Erro visível para combinação sem peça.** `autotile` lança `Error` com mensagem contendo: máscara, coordenadas (x,y,z), terreno. A mensagem está em pt-BR.

4. **`missingMasks` para diagnóstico.** Se o tileset não cobre as 16 combinações, o editor pode chamar `missingMasks` e mostrar quais faltam.

5. **`affectedCells` para propagação.** Quando um bloco muda, não é só a célula dele que precisa de re-ladrilhar — os 4 vizinhos também, porque a máscara deles mudou. `affectedCells` devolve a lista das 5 células.

6. **`findTileForMask` cruza mask + terrain.** Na fixture, `mask=5` aparece tanto para `wall` (tile_index=1) como para `doorway` (tile_index=4). O cruzamento com `terrain` desambigua.

### Limitações conhecidas

- **Apenas `edge/4` (Wang por aresta).** A fixture também tem regras `corner/4` e `outline`, mas o autoladrilhamento actual só usa a máscara de vizinhança simples. As regras `corner/4` são devolvidas por `findTileForMask` se a máscara bater, mas a sua semântica (dois bits por canto) pode não ser a ideal.
- **A fixture sintética é incompleta.** Para `wall`, apenas 5 das 16 máscaras têm peça (0, 3, 5, 10, 12). Isto é esperado — o código lida correctamente com a ausência.
- **`autotile` não re-ladrilha vizinhos.** A função apenas calcula o tile para UMA célula. A orquestração (chamar `autotile` para cada célula em `affectedCells`) deve ser feita pela ferramenta de pintura (F2-07) ou pela integração futura.

## F2-09 — Exportar project.json mais atlas

### Arquivos

- `tools/map-builder/src/export.ts` — Motor de exportação
- `tools/map-builder/src/export.test.ts` — 18 testes

### API pública

#### export.ts

```ts
export async function exportProject(
  project: ProjectV1,
  projectDir: string,
  outputDir: string,
): Promise<void>

export async function verifyExport(
  outputDir: string,
  project: ProjectV1,
): Promise<void>
```

- `exportProject`: Exporta `project.json` (atomicamente via `saveProject` do iso-core) + copia todos os atlas referenciados para `outputDir`, preservando caminhos relativos. Verifica existência de cada atlas ANTES de copiar. Lança `Error` em pt-BR com os nomes dos ficheiros em falta.
- `verifyExport`: Verifica que `outputDir` contém `project.json` e todos os atlas listados no projecto. Útil para validação pós-exportação.

### Decisões de design

1. **Caminhos RELATIVOS ao arquivo de projecto.** `projectDir` é o directório onde o projecto reside; os caminhos em `project.atlas` são resolvidos relativamente a ele. A exportação preserva a estrutura de subdirectórios dos atlas.

2. **Verificação ANTES de copiar.** `exportProject` faz `access()` em todos os atlas primeiro. Se algum faltar, lança erro ANTES de tocar no directório de saída — ou seja, `project.json` NÃO é escrito se a exportação falhar.

3. **Escrita atómica via iso-core.** `saveProject` (de F0-11) escreve para `.tmp` e renomeia — a exportação herda esta atomicidade.

4. **`verifyExport` como função separada.** Permite validação independente da exportação (ex.: CI, smoke tests). Verifica `project.json` + todos os atlas.

5. **Erro com nome do ficheiro.** A mensagem de erro inclui os nomes exactos dos atlas em falta, entre aspas, para facilitar o diagnóstico.

### Limitações conhecidas

- **Não copia dependências transitivas.** Se um atlas `.pixellab.json` referenciar texturas por caminho relativo, essas texturas NÃO são copiadas. A exportação actual apenas copia os ficheiros listados em `project.atlas`.
- **Não faz hash ou verificação de integridade.** A exportação confia que o conteúdo do ficheiro é o esperado; não calcula checksums.
- **Não actualiza `project.data`.** O campo `data` (ISO-8601) mantém o valor original do projecto. Idealmente a exportação deveria actualizá-lo para a data actual, mas isso alteraria o projecto passado por referência.

## Destinatários nomeados

- **Integração de F2-08 com F2-07 (pintura):** Quando `pintarChao` ou `apagarChao` alterar um bloco, o editor deve:
  1. Obter as `affectedCells` (central + 4 vizinhos).
  2. Para cada célula afectada que tenha um bloco, chamar `autotile` com as regras carregadas.
  3. Se `autotile` lançar (máscara sem peça), mostrar o erro e NÃO actualizar o tile visual — manter o estado anterior ou mostrar um placeholder de erro.
  4. Usar `missingMasks` no arranque para avisar o utilizador se o tileset estiver incompleto.

- **Integração de F2-09 com o editor:** O comando "Exportar" no editor deve:
  1. Pedir ao utilizador um directório de destino.
  2. Chamar `exportProject(project, projectDir, outputDir)`.
  3. Se lançar, mostrar o erro com os nomes dos atlas em falta.
  4. Se tiver sucesso, opcionalmente chamar `verifyExport` para confirmação.

- **F2-08 depende de F2-04 (tile-rules).** As regras vêm do parse de `RawTilesProResponse`. O editor precisa de obter esta resposta (via API ou fixture) e passá-la a `parseTileRules` antes de poder usar `autotile`.

- **F2-09 depende de F0-11 (iso-core/project).** `exportProject` usa `saveProject` para a escrita atómica e `loadProject` nos testes de round-trip.
